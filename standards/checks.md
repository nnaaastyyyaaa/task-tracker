# Перелік перевірок task-tracker

## Запуск усіх перевірок

```bash
npm run check
```

Команда виконує перевірки в такому порядку й зупиняється на першій, що не пройшла:

1. `npm run format:check`
2. `npm run lint`
3. `npm run test`
4. `npm run build`

## Перевірки

### 1. Форматування: `npm run format:check`

- **Команда:** `prettier --check .`
- **Що перевіряє:** форматування всіх файлів відповідає єдиному стилю Prettier. Файли не змінює.
- **Якщо не пройшла:** виконати `npm run format` (`prettier --write .`), що автоматично виправить форматування, і додати зміни до коміту.

### 2. Лінтер: `npm run lint`

- **Команда:** `eslint . --ext .js`
- **Що перевіряє:** усі `.js`-файли на помилки в коді (невикористані змінні, недосяжний код, неоголошені змінні тощо) та порушення правил ESLint.
- **Якщо не пройшла:** виправити зауваження за виводом ESLint.

### 3. Тести: `npm run test`

- **Команда:** `vitest run`
- **Що перевіряє:** усі автоматичні тести проходять. `run` означає одноразовий запуск без режиму спостереження.
- **Якщо не пройшла:** виправити код або тест за виводом Vitest.

### 4. Збірка: `npm run build`

- **Команда:** `node --check ./src/server.js`
- **Що перевіряє:** у точці входу `src/server.js` немає синтаксичних помилок. Файл не виконується.
- **Обмеження:** поки що перевіряється лише цей файл, у майбутньому ця команда буде замінена на реальний build.
- **Якщо не пройшла:** проаналізувати повідомлення про помилку, виправити відповідну синтаксичну помилку та повторно запустити npm run build

## Автоматичний запуск перед комітом

- **Хук:** pre-commit виконує `npm run check`.
- **Встановлення:** хук підключається автоматично скриптом `prepare` (`husky`) під час `npm install`.
- **Наслідок:** якщо будь-яка з перевірок не пройшла, коміт не створюється, доки помилку не виправлено.

## Допоміжні команди (не є перевірками)

| Команда          | Призначення                                               |
| ---------------- | --------------------------------------------------------- |
| `npm run format` | Автоматично виправляє форматування (`prettier --write .`) |
| `npm start`      | Запускає застосунок (`node ./src/server.js`)              |

## Що перевірки не покривають, і потребує саме ручної перевірки

- Відповідність реалізації файлу `spec.md`.
- Актуальність `README.md` та ADR.
- Відсутність секретів у репозиторії.
- Повний ручний сценарій роботи застосунку.
